| `WFC803` | `breaking-interface-change` | Contracts | 🔴 error |

## Why it matters

Callers written against the locked interface will fail (unknown or missing input) or silently read empty outputs. In large pipelines those callers may live in other repositories or rarely-run branches.

## How to fix

Update every caller first (wfc lists the known consumers), then regenerate the contract. If the change is intended, `wfc generate` records it and the diff makes the break explicit in review.

## Example

<Tabs items={["Problem", "Fixed"]}>
<Tab value="Problem">

```yaml
# contract: input "channel" optional
on:
  workflow_call:
    inputs:
      channel: { type: string, required: true }   # now required
```

</Tab>
<Tab value="Fixed">

```yaml
# keep it optional with a default (a required workflow_call input ignores its default),
# or update all callers first, then: wfc generate
      channel: { type: string, required: false, default: stable }
```

</Tab>
</Tabs>

## Configure

Change the severity (or turn the rule off) in `.github/workflow-contracts/wfc.config.yml`, by code or by name:

```yaml title=".github/workflow-contracts/wfc.config.yml"
rules:
  WFC803: off
  # or: breaking-interface-change: error
```

Explain it in the terminal:

```sh
wfc explain WFC803
```
